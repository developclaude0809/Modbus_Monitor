# 🧭 RR Mode 高速畫圖通訊與流程說明（Data Group Index 版）

---

## 📘 模式概要

RR Mode（Rapid Response Mode）是裝置的**高速畫圖通訊模式**。  
它與一般的 **03 Mode（監控模式）** 共用同一套繪圖模組，  
但在 RR Mode 下，資料來源改為高速報文串流。  

RR Mode 與 03 Mode 為**獨立模式**，使用者可自由切換，  
系統不會自動返回 03 Mode。

---

## ⚙️ 通訊報文結構概覽

| 階段 | 方向 | 報文格式 | 說明 |
|------|------|-----------|------|
| 握手 | 主機→裝置 | `52 52 00 [page] 00` | 選擇要讀取的資料頁（page = 0~12） |
| 確認 | 裝置→主機 | `52` | 裝置確認握手成功 |
| 資料請求循環 | 主機→裝置 | `52 52 01 00 00` | 固定請求報文（無 retry） |
| 資料回覆 | 裝置→主機 | `72 [ii jj] [Data1] [Data2] [Data3] [Data4] 0D` | 傳送一組資料（每組含 4 筆 data） |
| 結束 | 裝置→主機 | `58` | 表示資料傳輸結束 |

---

## 🧩 四個主要階段

### ① 握手階段（Handshake）

- 指令格式：`52 52 00 [page] 00`
- `[page]` 範圍：0~12（對應不同資料頁）
- 裝置回覆：`52` 表示成功

範例：  
`52 52 00 05 00` → 請求第 5 頁資料  
回覆 `52` → 握手成功

---

### ② 資料請求循環（Streaming Loop）

- 指令固定：`52 52 01 00 00`
- 收到完整資料幀（`72 ... 0D`）後，**立即再次發送**同一請求。  
- 若逾時或掉包，**不重送**上一筆，只進入下一輪。
- 循環直到：
  - 收到 `58`（裝置主動結束），或
  - 使用者手動按「停止畫圖」。

---

### ③ 資料幀解析（Data Frame Parsing）

#### 範例幀：
```
72 00 02 00 00 FF F9 00 01 00 00 0D
```

| 位元組範圍 | 內容 | 說明 |
|-------------|------|------|
| [0] | `72` | 回覆開頭 |
| [1..2] | `00 02` | **Data Group Index** (Big-Endian: 0×256+2=2，該頁第 2 組資料) |
| [3..4] | `00 00` | 第 1 筆 data (Big-Endian) |
| [5..6] | `FF F9` | 第 2 筆 data (Big-Endian) |
| [7..8] | `00 01` | 第 3 筆 data (Big-Endian) |
| [9..10] | `00 00` | 第 4 筆 data (Big-Endian) |
| [11] | `0D` | 回覆結尾 |

> 每幀固定長度：**12 bytes**
> 含 4 筆 16-bit 資料（Data1~Data4）

---

### 🧮 Data Group Index（X 軸）

- `72 [ii jj]` 這兩個位元組代表「該頁的第 N 組資料」。
- 主機以 **Big-Endian** 解讀：
  ```text
  DataGroupIndex = ii * 256 + jj
  ```
  其中 `ii` 為高位元組（frame[1]），`jj` 為低位元組（frame[2]）
- 這個值即為 **X 軸**。
- 裝置每傳一組資料，該索引自動加 1。

#### 範例序列：
```
72 00 00 ... → 第 0 組  (0*256 + 0 = 0)
72 00 01 ... → 第 1 組  (0*256 + 1 = 1)
72 00 02 ... → 第 2 組  (0*256 + 2 = 2)
72 00 03 ... → 第 3 組  (0*256 + 3 = 3)
72 00 04 ... → 第 4 組  (0*256 + 4 = 4)
```
X 軸值依序為 0, 1, 2, 3, 4。

#### 更多範例：
```
72 01 00 ... → 第 256 組  (1*256 + 0 = 256)
72 01 01 ... → 第 257 組  (1*256 + 1 = 257)
72 FF FF ... → 第 65535 組 (255*256 + 255 = 65535)
```

#### Wrap-around
- Data Group Index 為 16-bit 計數器（0x0000~0xFFFF）。  
- 由 0xFFFF 回到 0x0000 時，視為新循環，可重置或斷軸。

---

### ④ 資料繪圖（Plotting）

#### 🔹 模式流程

```
切換至 RR Mode
   ↓
載入 .dtbpt 標題檔
   ↓
選擇 Page（0~12）
   ↓
按下「Plot」→ 握手 + 啟動循環
   ↓
收到資料 → 解析 + 繪圖更新
   ↓
收到 58 或手動停止 → 結束資料循環
   ↓
仍停留在 RR Mode（不自動回到 03 Mode）
```

---

## 🗂️ `.dtbpt` 標題檔

- 定義每頁的 4 個項目標題
- 於切換至 RR Mode 時讀取一次
- 格式簡單、以逗號分隔

```text
# page0
A1,A2,A3,A4
# page1
V1,V2,V3,V4
# page2
Temp1,Temp2,Temp3,Temp4
# page3
Speed,Current,Power,Freq
# page4
In1,In2,In3,In4
...
# page12
X1,X2,X3,X4
```

選擇 page=3 → 對應標題：  
`Speed, Current, Power, Freq`

---

## 📊 繪圖模組行為（RR Mode）

| 項目 | 行為 |
|------|------|
| X 軸 | **Data Group Index（ii + 256×jj）** |
| Y 軸 | Data1~Data4 的數值 |
| 曲線 | 固定 4 條，標題來自 `.dtbpt` 對應頁 |
| 更新頻率 | 每收到一幀即時更新一次 |
| 顯示範圍 | 可設定顯示最近 N 組資料 |
| 結束條件 | 收到 `58` 或使用者按停止 |
| 結束後狀態 | 停止資料循環，仍維持 RR Mode |

---

## 🔎 健壯性與例外處理

| 狀況 | 處理方式 |
|------|-----------|
| 掉包 / 亂序 | 依 Data Group Index 定位 X 軸位置；可留空或插值 |
| 跳號 | 統計缺幀數（ΔIndex - 1）作為診斷指標 |
| Wrap-around | Index 由高值回到低值 → 視為新循環，重新開始或斷軸 |

---

## ✅ 總結

- **每筆報文 (`72 ... 0D`) = 一組資料（Data Group）**
- **X 軸 = Data Group Index**（由裝置自增）
- **Y 軸 = 該組內 4 筆 Data**
- `.dtbpt` 只定義標題，畫圖時自動套用
- RR Mode 流程：握手 → 事件驅動請求 → 解析 → 畫圖
- 結束 RR Mode 後不會自動回到 03 Mode，由使用者決定
